## Executive Summary

The changes in #515 fulfill the approved specification (`docs/specs/2026-09-10-ensure-assets-visible.md`) and implementation plan (`docs/plans/2026-09-10-ensure-assets-visible.md`). The implementation successfully:

1. Makes on-disk unmanaged assets visible across all asset kinds (skills, agents, commands, Pi extensions) as `unlisted` or `local package · untracked` without silently adopting or mutating them.
2. Implements explicit, lossless import repair for unmanaged skills and Pi local packages via `--repair`, guarded by mandatory individual confirmation prompts (`[y/N/q]`, defaulting to `N`).
3. Guarantees zero mutation of Pi `settings.json` and source directories during both discovery and repair.
4. Enforces strict boundary isolation and symlink safety: escaping symlinks are rejected, dangling symlinks do not crash, and hidden/backup directories are ignored.
5. Employs stable identifiers for nested bundle skills (`<bundle>:<subskill>`).
6. Ensures full CLI and TUI consistency between doctor audit reporting and TUI grid state.
7. Resolves the regression in `test_global_pi_uses_standard_projection` via commit `796af17`, ensuring proper propagation of the `home` parameter.

## Detailed Review Criteria Assessment

### 1. Spec and Plan Conformance
- **Spec:** `docs/specs/2026-09-10-ensure-assets-visible.md`
- **Plan:** `docs/plans/2026-09-10-ensure-assets-visible.md`
- **Acceptance Criteria Verification:**
  - **Criterion 1 (Pi Local Packages):** `_pi_settings.read_package_records()` and `pi_extension_inventory.build_inventory()` classify filesystem packages from `settings.json` as `origin="local-package"`, `displayOrigin="local-package untracked"`, distinct from registry `npm:` packages. Precedence of lock-backed entries is preserved.
  - **Criterion 2 (Skills, Agents, Commands TUI Rows):** `build_skill_rows()`, `build_agent_rows()`, and `build_command_rows()` compute the union of lockfile rows and bounded filesystem discoveries. Discovered assets absent from lockfiles are assigned `state="unlisted"` and `source="untracked"`, with harness adapter cells correctly probed and displayed.
  - **Criterion 3 (Skill Bundles & Stable IDs):** `discover_unmanaged_skills()` discovers top-level skills as well as nested skills in bundle directories (`<bundle>/skills/<subskill>` or `<bundle>/<subskill>`), producing deterministic identifiers formatted as `<bundle>:<subskill>` (e.g., `superpowers:brainstorming`).
  - **Criterion 4 (Doctor Audit & Safe Repair):** `skill doctor` and `pi-extension doctor` report unmanaged assets as `unmanaged` findings. Without `--repair`, findings have `fix_action=None` (strictly report-only). With `--repair`, interactive confirmation is required.
  - **Criterion 5 (Home-aware Skill Lock Path):** `skill_paths.lock_file_path(scope="global", home=home)` delegates to `library_lock_path(home=home)` and `_paths_core.library_root_for_asset_type(..., home=home)`, honoring explicit `home` while retaining environment variable (`$AGENT_TOOLKIT_SKILLS_ROOT`) precedence.
  - **Criterion 6 (Comprehensive Testing):** Tests cover path resolution, local package classification, bundle traversal, report-only/decline/repair workflows, and TUI rendered evidence.
  - **Criterion 7 (Test Isolation & Visual Evidence):** Automated headless Textual tests generate rendered evidence under `assets/verification/515/` (`inventory.json` and `inventory.svg`).

### 2. Safety & Non-Mutation Guarantees
- **Confirmed Repair Only:**
  - Running `skill doctor` or `pi-extension doctor` without `--repair` sets `fix_action=None`. Unmanaged assets are reported, but no prompt is shown and no changes are written.
  - Passing `--no-fix` explicitly skips all fix actions regardless of `--repair`.
  - When `--repair` is supplied, each finding prompts `apply? [y/N/q]` with `default="N"`. Pressing Enter or entering `N` declines the fix non-destructively.
  - Non-interactive execution (CI/closed pipe) cleanly catches EOF/abort and defaults to stopping without mutating.
- **Zero Mutation of Pi `settings.json`:**
  - `_make_import_package_action()` in `pi_extension_doctor.py` updates only the lockfile (`pi-extensions-lock.json`). It does not modify, rewrite, or touch `settings.json`.
  - Verified by `test_pi_doctor_repair_confirmed_imports_package_losslessly`: `settings.json` content is asserted byte-for-byte identical before and after confirmed repair.
- **Repeat-Repair Idempotence:**
  - Both `_make_import_skill_action` and `_make_import_package_action` check `if slug in cur_lock.skills: return`. Subsequent runs report `✓ all clean` without duplicate entries or errors.
- **Lock-Write Failure Safety:**
  - If lock write fails, source asset directories and settings files are untouched because actions only mutate the lock target.

### 3. Lossless Behavior & Observational Discovery
- **Source Byte Preservation:** Discovered unmanaged assets are left exactly where they reside on disk. The import actions record the source path in `LockEntry(source=..., source_type="local")` without copying, moving, or deleting files.
- **Bundle Layout Preservation:** For bundle sub-skills (`<bundle>:<subskill>`), `skill_path` is correctly calculated relative to the bundle root (e.g. `skills/brainstorming`), preserving the bundle hierarchy in the lockfile.
- **Unsupported / Settings-Only Entries:** Non-filesystem or unrepresentable entries remain reported as unmanaged rather than coerced into an invalid lock entry.

### 4. CLI and TUI Consistency
- **Grid State & Display Names:**
  - TUI widgets (`SkillGrid`, `AgentGrid`, `CommandGrid`) display unmanaged rows with state `unlisted` and source `untracked`.
  - `PiGrid` displays unmanaged local packages with origin badge `[yellow]local package · untracked[/]`.
  - `display_names.py` includes `"local-package": "local package (untracked)"`.
- **Non-Interactive TUI Safety:**
  - In `PiGrid._on_data_table_cell_selected()`, rows with `origin in ("untracked", "local-package")` immediately return. Users cannot accidentally toggle or mutate untracked rows via the TUI spacebar action.
  - `_cell_glyph()` renders untracked glyph (`—`) for both untracked loose extensions and local packages.
  - `_info_body()` presents clear contextual explanation indicating that local packages are unmanaged declarations in `settings.json`.

### 5. Path Isolation & Sandbox Safety
- **Symlink Escape Protection:**
  - `_is_inside(child, parent)` verifies `child.resolve().relative_to(parent.resolve())`.
  - Symlinks pointing outside the scan root are skipped (`test_filesystem_discovery_escaping_symlink_ignored`).
- **Dangling Symlink Handling:**
  - Dangling symlinks are safely caught (`not target.exists()`) and skipped without raising uncaught exceptions (`test_filesystem_discovery_unmanaged_standalone_and_bundle`).
- **Directory Filtering:**
  - Hidden directories (`.name`), `_parents`, and backup artifacts (`*.bak-*`) are ignored during discovery across skills, agents, commands, and packages.
- **Home Scoping:**
  - Global paths honor explicit `home` argument across `_paths_core.py` and `skill_paths.py`.
