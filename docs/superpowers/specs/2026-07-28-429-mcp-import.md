# MCP Import Design Spec

**Issue:** [#429](https://github.com/ajanderson1/agent-toolkit-cli/issues/429)
**Status:** implementation-ready
**Decision authority:** #429 acceptance criteria; CTO decisions, 2026-07-28

## Goal

Add `agent-toolkit-cli mcp import <file>` to reconstruct the local global library from another machine's `mcps-library.json` manifest. This provides cross-machine sync parity with the `skill`, `agent`, and `pi-extension` types, without introducing an `export` artifact.

## Scope and decisions

- **Library Manifest Source:** The import file MUST be a valid `mcps-library.json` envelope (from #481). `mcps-lock.json` is a projection record, not an authoring spec; passing it must fail loud with an explanatory error.
- **Additive Merge:** Import applies a total skip-if-exists strategy. An entry is skipped if its slug exists in the local manifest or physical directory, preserving existing modifications or drifted files.
- **`--local` Hard-skip:** Local entries embed absolute source-machine paths. They must be hard-skipped during import to prevent invalid commands. An explicit message directs the user to re-add them manually.
- **Secret Hygiene:** Every candidate entry must pass the centralized `assert_safe_entry` before processing. Unsafe legacy literals in the imported file cause a hard skip of that entry (quarantine), with redacted diagnostics identifying the field path.
- **Manifest Persistence:** After processing each valid addition, the manifest is appended and then materialised atomically. A crash or interrupt mid-import leaves a correct inventory and a resumable state.
- **No Projection:** Imported servers are placed in the library but NOT installed. They do not appear in `mcps-lock.json`. A post-run note explicitly instructs the user to run `mcp install`.
- **`--latest` Resolution:** By default, entries maintain the `resolved_version` and args from the source manifest. When `--latest` is provided, pinned specs (like npx/uvx/local) re-resolve to current HEAD/version using `update_cmd`'s `_reresolve`.

## Validation Rules

1. `read_manifest` will structurally validate the envelope (must be v1 JSON with `"mcps"` mapping).
2. If `file.name == "mcps-lock.json"`, emit a clear warning that the lock file does not contain server authoring specs and direct the user to supply `mcps-library.json`.
3. If an entry's `install_method` is `"local"`, skip it with `skipped  {slug}  (local paths cannot be imported)`.
4. Run `assert_safe_entry(entry)` for each entry. If it throws `UnsafeMcpSpecError`, skip the entry with `skipped  {slug}  (unsafe literal in {field} - value redacted)`.
5. Use `scan_entry_files(library)` and `read_manifest` to determine existence. A slug is skipped if it exists in either.

## Materialisation & Output

- For each added entry:
  - If `--latest`, re-resolve using `_reresolve(entry, slug)`.
  - Add to the manifest dictionary and write to `~/.agent-toolkit/mcps-library.json`.
  - Call `materialize_entry(library, entry, overwrite=False)`.
  - Echo `  added    {slug}  <- {entry.source} {suffix}`. If it fails, report in `failed` list and do not halt.
- Output summary prints added, skipped, and failed counts, followed by notes confirming that imported items are not installed automatically.

## Parity

The output formatting and notes exactly match `skill import` where possible. The main deviation is that MCPs have no `--latest` concept for unpinned specs (e.g., Docker tags like `:latest` or raw URLs), which are documented as floating anyway.
